
## Ключевые принципы интерфейса

- **Минимум “магии”**: всё на обычных контролах (поля ввода, кнопки, чекбоксы, таблицы, многострочные логи).
- **Тёмная тема**: комфортно для длительной работы и хорошо читаемо.
- **Состояния и подсказки**: важные события (подключение, запуск, автозапуск плагинов) отражаются в логах.
- **Ориентация на доступность**: интерфейс проектировался так, чтобы им можно было пользоваться **клавиатурой** и **скринридерами** (NVDA/JAWS/прочие).

---

## Доступность (скринридеры и клавиатура)

Интерфейс рассчитан на работу без мыши:

- **Tab / Shift+Tab**: переход по элементам управления.
- **Enter / Space**: активация кнопок и переключение чекбоксов.
- **Стрелки**: навигация по спискам и таблицам (например, список кнопок главного меню, список плагинов).
- **Читаемые подписи**: у полей ввода есть текстовые метки (“Токен”, “PIN-код”, “Адрес API”…), что помогает скринридеру корректно озвучивать контекст.
- **Логи как обычный текст**: окно логов можно читать построчно, копировать, прокручивать.
- **Снижение “словесного шума”**: в главном окне есть чекбокс **«Фильтровать дубли логов»**.

> В окне настройки видимости кнопок прямо подсказано управление: **стрелки вверх/вниз** выбирают пункт, а **Space/Enter** переключают его.

## 1) Главное окно AutoCraft Bot

**Окно:** `AutoCraft Bot v1.1.7`  
Основная панель для запуска/настройки бота и просмотра логов.

### Блок авторизации/параметров бота

Сверху расположены поля:

- **Токен**: поле ввода токена Telegram-бота.
- **PIN-код**: поле ввода PIN для авторизации пользователей.
- **ID аккаунтов**: поле для списка Telegram ID (пример в подсказке: `1234567, 1234567890`).

### Блок Telegram API

Раздел **Telegram API** управляет тем, куда бот подключается:

- **Адрес API**: например`127.0.0.1`
- **Порт API**: например`8081`
- Чекбокс **«Использовать стандартный сервер Telegram API»**  
  Если включить, бот ориентируется на “обычный” (не локальный) API.

> На правой стороне окна виден вертикальный скролл: интерфейс не ломается даже на небольших экранах.

### Блок «Логи»

Нижняя часть окна:

- Строка состояния: например **«Бот запущен.»**
- Чекбокс **«Фильтровать дубли логов»**
- Большое многострочное поле логов со скроллом.

Пример того, что фиксируется в логах:
- старт приложения и инициализация GUI,
- загрузка `config.ini/credentials`,
- подключение к локальному Telegram API (`127.0.0.1:33433`),
- завершение сканирования/автозапуска плагинов и их количество.

## 2) Окно “telegram-bot-api-server” (локальный Telegram Bot API)

**Окно:** `telegram-bot-api-server`  
Это отдельная утилита, которая поднимает локальный Telegram Bot API (для работы без ограничений публичного сервера и для локальной инфраструктуры).

### Параметры сервера

- **API ID** и **API Hash** (поля ввода, с примерами-плейсхолдерами).
- Чекбокс **Local Mode**.
- **Listen IP** (например `0.0.0.0`)
- **Port** (например `33433`)
- **Max Webhook Connections** (спинбокс)
- **Уровень логирования** (спинбокс)
- Ограничители интерфейса логов:
  - **Макс. размер UI-логов (МБ)**
  - **Макс. строк UI-логов**
  - **Макс. строк API-логов**
  - **Обновление логов (мс)**
- Чекбокс **«Сохранять API-логи в файл (console)»**
- Пути к файлам/каталогам (каждый с кнопкой `...`):
  - **Data Dir**
  - **Temp Dir**
  - **Server EXE**
- Чекбокс **«Автопоиск путей (рядом с программой)»**
- Чекбокс **«Автостарт при запуске»**

### Управление

Кнопки:

- **Старт**
- **Стоп**
- **Сохранить**
- **Свернуть окно**

Внизу предусмотрены области логов:
- **UI Логи**
- **API Логи**

## 3) Окно “Функции”

**Окно:** `Функции`  
Это “хаб” дополнительных инструментов. В нём прямо написано, что кнопки могут **собираться автоматически из модулей** рядом с файлом окна.

Текст-пояснение в окне:
- Здесь живут дополнительные окна и инструменты.
- Чтобы добавить новую функцию, нужен модуль с:
  - `FUNCTIONS_BUTTON_TEXT`
  - `FUNCTIONS_ENTRYPOINT`
- Файл окна редактируется отдельно: `gui_win/functions_window.py`

### Доступно сразу

Кнопки, показанные на скриншоте:

- **Менеджер плагинов**
- **Главное меню (видимость)**
- **Диагностика окружения**

Есть кнопка **«Закрыть»**.

## 4) Менеджер плагинов

**Окно:** `Менеджер плагинов`  
Назначение: управление жизненным циклом плагинов (установка/обновление, запуск/выгрузка, удаление, автозапуск).

### Таблица плагинов

Таблица со столбцами:

- **Плагин** (имя)
- **Статус** (например “Установлен”, “Не установлен”)
- **Автозапуск** (например “нет”)
- **Папка** (путь к директории плагина)

Подсказка над таблицей: **«Дважды кликните по плагину для действий.»**  
(При работе с клавиатуры обычно это эквивалентно переходу на строку и выполнению действия через кнопки ниже.)

### Действия

Кнопки управления:

- **Обновить список**
- **Установить/обновить**
- **Запустить**
- **Выгрузить**
- **Удалить**
- Чекбокс **Автозапуск**
- **Открыть папку**

### Лог операций

Ниже есть поле **«Лог операций менеджера плагинов.»** для сообщений о действиях (что установилось, что запустилось, что удалилось и т.д.).

Кнопка **«Закрыть»** завершает работу окна.

## 5) Настройки видимости кнопок главного меню

**Окно:** `Настройки главного меню бота`  
Здесь включается/выключается показ отдельных кнопок в **главном меню бота**.

### Как управлять (важно для доступности)

Внутри окна написано:

- **Стрелки вверх/вниз** выбирают кнопку.
- **Space или Enter** переключают галочку.
- Изменения **сразу сохраняются** в `config.ini` в секции **`[mainmenu_visibility]`**.
- Кнопка **«Вернуть по умолчанию»** снимает все галочки.

### Список кнопок

Каждый пункт показывает имя и текущее состояние (включена/выключена), например:

- **Выполнить win+r — выключена**
- **Файловый менеджер — включена**
- **Работа со службами — выключена**

Кнопки управления:

- **Обновить**
- **Вернуть по умолчанию**
- **Закрыть**

## 6) Диагностика окружения

**Окно:** `Диагностика окружения`  
Окно для проверки среды, сборки диагностической информации и быстрого доступа к папкам EXE.

### Быстрые действия

Слева расположены кнопки:

- **Открыть временную папку EXE**
- **Открыть папку с EXE**

Ниже отображается путь к активному `config.ini` (пример на скриншоте):
- `D:\soft-programming\programming\vscod\tgbot\testwork\config.ini`

Есть чекбокс-индикатор:
- **Debug в config.ini**

### Сбор диагностики

Кнопки:

- **Показать диагностику**  
  Выводит информацию в правую текстовую область.
- **Копировать диагностику**
- **Тестовая запись в лог**

### Тесты на “жёсткие” случаи

Ниже отдельные кнопки для проверки механизмов устойчивости:

- **Аварийное завершение**
- **Зависание программы**

Справа находится большое поле вывода, куда появится диагностика после нажатия **«Показать диагностику»**.

Кнопка **«Закрыть»** завершает окно.

Скриншоты явно указывают на структуру проекта:

- Настройки видимости главного меню сохраняются в `config.ini` → секция **`[mainmenu_visibility]`**.
